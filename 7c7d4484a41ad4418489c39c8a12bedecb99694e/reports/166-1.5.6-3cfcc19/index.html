Feature:Project task — how many reported times still await release 5s 874ms 1

A Bereichsleiterin opens a task and sees, as a stat button, how many
timesheet entries on it still need her release; clicking it opens exactly
those entries, where she validates them. This is deliberately end-to-end for
two reasons the unit level cannot reach. First, the button has to survive
view combination: project.view_task_form2 is inherited by hr_timesheet,
project_enterprise, timesheet_grid and this module, and an arch assertion
proves only that the xpath applied, not that the button rendered in the
assembled form. Second, this is an access rule as the user experiences it —
before #324 a Bereichsleiterin could not see her team's entries at all, so
the number she gets after a real login is the behaviour under test.
The counting rules themselves (validated, absence and public-holiday
exclusion, the project rollup, the action domains) are unit tests in
wolfinne_ifms_customization/tests/test_timesheet_validation_indicator.py, and
the record rule in wolfinne_ifms_access/tests/test_timesheet_scope.py — none
of that is re-proven here. The absence/public-holiday exclusion in particular
cannot be set up from a browser at all: project_timesheet_holidays refuses to
let a non-superuser create or modify a leave-linked timesheet line
(_check_can_create / _check_can_write), so that case belongs to the unit
level by construction.
